# Household review reference

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Household members reviewing proposed work and agent research. This reference uses only invented records.

## Product Purpose

Let a person see the finding, the evidence that is actually available, what remains unknown, and the specific decision requested. Reduce the effort of supervising assistance while preserving human authority.

## Operating Context

This is the household-domain review surface for the existing life work plane. It is source-only preparation; real account acceptance is deferred. The default experience is a clearly labeled local example. A connected deployment supplies a separately verified human session and an explicit board/grant binding.

## Capabilities and Constraints

- Review queue and item detail use bounded, versioned packets.
- Ready for research, record completion with evidence, and dismiss are existing decisions. Scheduling is excluded until date semantics are explicit.
- Workers submit research; a separate human client/grant is required to decide.
- Unknown dates and model details remain unknown. Source text has no decision authority.
- All references are inert text. This screen does not retrieve source contents, contact people, spend money, or execute work.
- A failed or ambiguous write is not automatically retried.
- No real records, names, identifiers or private infrastructure belong in this public repository.

## Implementation

For this reference, use browser-native HTML, CSS and ES modules with no runtime frontend dependency. This is an implementation choice for the current build, not a claimed standing user preference. The host authentication integration is an explicit separate boundary; there is no token-entry form, stored browser credential or automatic session discovery.

## Evidence on Hand

The existing life work-plane and authenticated worker adapter, plus a new dedicated human-review contract and a synthetic furnace-baseline package. No real furnace inventory or service history is supplied.

## Product Principles

- Make the requested decision obvious.
- Distinguish source statements, missing facts, human decisions and completed outcomes.
- Show less information with explicit coverage rather than imply completeness.
- Keep the example/connected distinction visible throughout the interaction.

## Accessibility

Use native controls, keyboard-visible focus, mobile reflow, semantic landmarks, live status announcements and reduced-motion support.
